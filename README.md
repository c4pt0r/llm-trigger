# llm-trigger

Describe a trigger in natural language, store it as a structured `IF / THEN` rule, and let an engine that **never calls a model** evaluate and execute it on a cron schedule.

```
$ node src/cli.js add "当 github 上 c4pt0r/jmp2.io 有新 release 而且不是预发布版时，记一条日志"
id: r_015fbbf9
IF/THEN: IF github.release.published (repo=c4pt0r/jmp2.io) WHEN prerelease eq false EVERY "*/10 * * * *" THEN log(text="新 release {{tag}}: {{url}}")
note: 当 c4pt0r/jmp2.io 发布非预发布版的新 release 时，记录一条日志。
guessed: every
model: qwen3.8-flash-next-iq3_s
```

Natural language in, structured rule out. Input can be Chinese or English; the stored artifact is always the same `{if, then}` object.

## Core design: the model only runs at compile time

| Stage | Who does it | How often |
|---|---|---|
| Natural language → structured rule | **a local model via pi** (`pi -p --mode json`, defaults to the current pi session model) | every time a rule is edited |
| Rule validity | `src/schema.js` validator, checked against the catalog in `src/catalog.js` | every write |
| Event detection + action execution | `src/engine.js` + `src/sources.js` + `src/actions.js`, plain code | every cron hit |

This is what makes "firing" reproducible, auditable and testable: a model can't hallucinate a POST to your webhook at 3am. The model may only pick events/fields/ops/actions that are **actually implemented** in `catalog.js`; if the sentence isn't expressible, it refuses outright:

```
$ node src/cli.js parse "当我飞书里收到老板消息时提醒我喝水"
rejected:
- model refused: The catalog does not support monitoring incoming messages from Feishu (Lark)...
```

When validation fails, the errors are fed back to the model for one repair round (`maxRounds`). If it is still invalid, the API returns 422 — a half-valid rule is never stored.

## LLM backend = pi (no OpenAI key)

`src/pi.js` spawns a one-shot, tool-less pi process and reads its JSONL event stream:

```
pi -p --mode json --no-session -nt -ns -np -nc --thinking off \
   --model $PI_PROVIDER/$PI_MODEL --system-prompt <compiler prompt> -- <natural language>
```

- `-nt -ns -np -nc` disables tools / skills / prompt templates / AGENTS.md. One compile costs ~60 input tokens and ~1s.
- The model defaults to the **current pi session model** (`PI_PROVIDER/PI_MODEL`). Without an explicit `--model`, pi falls back to its configured default provider, which on this machine fails with `Connection error.` — so `pi.js` pins it deliberately.
- Override with `LT_MODEL=provider/id`.

## Storage (SQLite via Node 22's built-in `node:sqlite`, zero dependencies)

`data/llm-trigger.db`:

- `rules`: `raw` (the original sentence) + `if_json` / `then_json` (structured) + `rendered` (a deterministic `IF ... WHEN ... EVERY ... THEN ...` string) + `source/event/action/every` **flattened into real columns**, so "which rules watch GitHub releases?" is one SQL statement. `state_json.seen` holds the dedup keys.
- `fires`: every fact seen, whether it matched the conditions, and the action status (`baseline` / `fired` / `no_match` / `dry` / `error` / `skipped`).

`rendered` is generated by code from the structured data, **not** written by the model — so the IF/THEN line in the UI is guaranteed to equal what actually executes.

## Event catalog (the extension point)

| event | source | dedup key | fields |
|---|---|---|---|
| `github.release.published` | github | tag | tag,name,url,published_at,prerelease,body |
| `github.issue.opened` | github | number | number,title,author,url,labels,created_at,body |
| `github.pr.opened` | github | number | number,title,author,url,draft,created_at |
| `github.pr.merged` | github | number | number,title,author,url,merged_at |
| `github.commit.pushed` | github | sha | sha,message,author,url,date |
| `github.star.count` | github | stars | stars,url |
| `http.json.changed` | http | value | value,status,url |
| `time.schedule` | time | now | now,date,time,weekday |

Condition ops: `eq ne contains not_contains matches gt gte lt lte in exists`
Actions: `log`, `webhook.post`, `lark.webhook`, `shell.exec` (requires `ALLOW_SHELL=1`)

Adding an event = one line in `catalog.js` (fields + dedup key) + one branch in `sources.js`. The validator and the prompt follow automatically, because all three read the same catalog.

## Usage

```bash
npm run cli -- add "有人在 c4pt0r/jmp2.io 提 PR，标题带 OOM 且不是 draft，就 POST 到 https://x/hook，每小时查一次"
npm run cli -- list
npm run cli -- run <id> --dry        # evaluate but do not execute actions
npm run cli -- run <id> --all        # ignore dedup history, replay every known event
npm run cli -- fires <id> --limit 20
npm run cli -- events | actions      # inspect the catalog
npm start                            # HTTP API + web UI + scheduler (127.0.0.1:8787 by default)
npm test
```

HTTP API: `POST /api/parse` (compile only), `POST /api/rules` (compile and store), `PUT /api/rules/:id` (hand-edited structured JSON, same validator), `PATCH /api/rules/:id` (enable/disable), `POST /api/rules/:id/run {dry,force}`, `GET /api/fires`, `GET /api/catalog`, `GET /api/health`.

## Two behaviours worth knowing

1. **The first check is a baseline.** A brand-new rule records the events that already exist as `baseline` and does not fire (otherwise adding a release rule would immediately hit your webhook 10 times). Replay deliberately with `--all` / `{"force":true}`.
2. **Dedup is once per event.** Every evaluated fact is written to `seen`, matched or not. A failing action is logged as `error` but is **not** retried automatically — that keeps a broken webhook from being hammered forever; retry manually with `run --all`.

## Security boundaries

- Binds to `127.0.0.1` by default; `shell.exec` only runs when the server has `ALLOW_SHELL=1`, otherwise it is logged as `skipped`.
- There is **no** API authentication yet. Do not expose this to the public internet.
- Unauthenticated GitHub API is limited to 60 req/h; set `GITHUB_TOKEN` for more.

## Known limits / next steps

- The catalog is a whitelist with three source families (github / http / timer). Webhook-in ("fire the moment someone pushes") needs an inbound route that feeds facts straight into `engine`.
- Single-process scheduler, no distributed lock; running several instances fires twice.
- Rules cannot be composed (no cross-event AND/OR) — one event plus a conjunction of conditions.
